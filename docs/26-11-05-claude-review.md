- В коде найдено одно место, где смена формата источника пройдёт молча, вопреки правилам проекта (см. Код, пункт 1).

### 2. Две поломки источника и что с ними сделано

1. **Изменился формат списка «No publicly available API» в JS-клиенте AA.** Раньше метка задавалась ссылкой `l.I.notPubliclyAvailable`, теперь — строкой `"No publicly available API"` прямо в коде. Скрипт корректно упал с понятной ошибкой. Парсер ([rating.py](../skills/ai-fair-rating/scripts/rating.py) `parse_unavailable_api_ids`) обновлён: теперь он ищет связку «список ID → строка метки → `"checkered"`». Это даже надёжнее: якорем служит сам текст метки. Список тот же — 7 ID.
2. **AA убрала из каталога поле `intelligenceIndexIsEstimated`.** Его нет ни у одной из 723 моделей. В прошлом снимке оно было `false` у **всех** 716 моделей, включая модели без балла, то есть ничего не различало. В Coding Agent данных `indexScoreIsEstimated` тоже отсутствует у всех 34 конфигураций. По решению владельца проекта новое правило: **любой конечный числовой балл считается результатом измерения, в обоих индексах**. Что изменено:
   - Intelligence: убрана проверка флага оценки.
   - Coding Agent: убраны исключения `estimated_score`, `incomplete_benchmarks`, `missing_measured_attempts`, сверка набора из трёх компонентов и среднего, а также жёсткая привязка к v2.0. Проверка шкалы `0..1` осталась: балл вне шкалы — ошибка.
   - В метаданных `estimated_scores_included` заменено на `score_status_filter: any_finite_numeric`, удалено `required_components`.
   - Обновлены `SKILL.md`, `README.md`, `AGENTS.md` и тесты.

   На сегодняшних данных старое и новое правило дают одинаковые графики: сегодня эти проверки никого не отсекали.

## Код: находки

Отсортированы по важности.

1. **Тихий обход проверки полноты каталога моделей** — `rating.py:60`. `parse_page` возвращает `max(counts, default=0)`. Если AA уберёт со страницы текст «N of M models», `declared_count` станет 0, и проверка `len(models) < declared_count` пропустит любой непустой каталог. Это противоречит правилу AGENTS.md: «A source format change must produce an actionable error». У Coding Agent парсера такая же ситуация уже обрабатывается как ошибка. Исправление — одна строка: при пустом `counts` выбрасывать `ValueError`, плюс тест.
2. **Частично обновлённый вывод при сбое** — `rating.py:609–613`. Выборки обоих индексов считаются до записи, это хорошо. Но Intelligence записывается до того, как Coding Agent проходит рендер и проверку вёрстки. Если проверка вёрстки Coding Agent упадёт, в `output/` окажется новый Intelligence рядом со старым Coding Agent. Внутри `write_result` PNG/SVG тоже пишутся раньше CSV/metadata. Это нарушает обещание SKILL.md «preserve existing output». Решение: рендерить оба индекса во временную папку и переносить готовые файлы в конце.
3. **Хрупкость источника** — `fetch_snapshot`, `decode_catalog`, `fetch_api_markers`. Каталог AA отдаётся зашифрованным (AES-GCM, ключ в странице), а список недоступных по API моделей вытаскивается регуляркой из минифицированного JS. Обе вещи AA может поменять в любой день: за неделю это случилось дважды. Кроме того, сайт явно не рассчитан на машинное чтение каталога. Стоит проверить условия использования AA и наличие официального API: если он есть, он устойчивее, хотя, скорее всего, потребует ключ и изменит обещание README «API-ключ не требуется». Это решение за владельцем, не обязательная правка.
4. **Скачиваются все JS-чанки на каждый запуск** — `rating.py:154–173`. Сейчас это 65 файлов (несколько МБ), нужен из них один. Терпимо. Сократить загрузку можно, только если сначала проверять чанк из прошлого снимка (`public_api_markers.source_url`) и обходить все файлы лишь при его отсутствии. Низкий приоритет.
5. **Рудименты в metadata.json** — `rating.py:562–564`. `restricted_effort: {}` всегда пуст и остался от старого ограничения на xhigh. `public_api_required: true` и `api_availability_field` — константы. Можно удалить `restricted_effort` и его проверку в `tests/test_rating.py:304`. Низкий приоритет.
6. **CRLF в JSON на Windows** — `rating.py:556, 579`. `write_text` без `newline="\n"` пишет `metadata.json` и `snapshot.json` с CRLF (SVG уже пишется с LF). `.gitattributes` нормализует при коммите, так что на Git это не влияет, но Git выводит предупреждение. Однострочная правка.
7. **Мелкие повторы.** Разбор «of N models» продублирован в `parse_page` и `parse_agents_page`; проверка ключей снимка продублирована в `main` для двух индексов. Хеш каталога моделей считается дважды (для Intelligence и для Coding Agent). Выносить в хелперы стоит только при следующей правке этих мест.
8. **Косметика графика.** Подзаголовок выглядит как `≥ Qwen3.8 27B (Xhigh) (20.11)` — двойные скобки. Можно писать `≥ 20.11 (Qwen3.8 27B Xhigh)`.

Что сделано хорошо: строгая проверка типов (`type(x) is bool/int`, а не truthy), отказ от выполнения JS, понятные сообщения об ошибках, воспроизводимость через снимки, автоматическая проверка вёрстки с числами в metadata. Тесты покрывают отбор, парсеры, replay и сохранность вывода при сбое загрузки.
